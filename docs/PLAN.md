# KBO Stat 기획서

작성일: 2026-08-31 · 상태: v1.1 (T1·T2·T7 완료 반영, T4 전제 정정, 과거 데이터 서술 정정)

---

## 1. 무엇을 만드는가

KBO 데이터를 **매일 자동으로 수집·가공해서, 한 화면에서 팀과 선수의 흐름을 읽게 하는 대시보드**.

기존 야구 사이트는 숫자를 보여주지만 "지금 이 팀이 왜 이런 흐름인지"는 사용자가 직접 조합해야 한다.
이 프로젝트는 수집(크롤러) → 가공(파생지표) → 저장(CSV/PostgreSQL) → 서빙(FastAPI) → 화면(React)까지
한 파이프라인으로 묶어서, 매일 갱신되는 해석 가능한 뷰를 만드는 것을 목표로 한다.

**성격**: 학습·포트폴리오 프로젝트. 상용 서비스가 아니며 데이터 권리는 각 원 출처(KBO, 네이버, Statiz)에 있다.

## 2. 대상 사용자

| 사용자 | 원하는 것 |
| --- | --- |
| KBO 팬 (주 사용자) | 오늘 경기, 우리 팀 순위·흐름, 관심 선수 기록을 빠르게 |
| 데이터에 관심 있는 팬 | 존별 타율, 월별 승률 같은 원 사이트에 없는 파생 지표 |
| 채용 담당자 / 리뷰어 | 수집~서빙까지 이어지는 엔드투엔드 구조와 코드 품질 |

## 3. 범위

**한다**
- 매일 1회 자동 갱신되는 팀/선수/일정 데이터
- 시즌 단위 조회 (2026 시즌 중심. 과거 1982~2025는 **선수 리더보드** CSV만 보유 —
  `data/raw/kbo_official/kbo_{연도}.csv` 45개는 `선수명` 컬럼을 가진 리더보드다.
  **팀 순위 CSV는 2026뿐**이다: `kbo_team_rank_2026.csv`·`kbo_team_rank_history_2026.csv`)
- 파생 지표: 타자 세부지표, 팀 월별 성적, 투구 존 분석
- AI 요약: 경기 프리뷰/리뷰, RAG 기반 질의응답

**안 한다 (Non-goals)**
- 실시간(분 단위) 중계·문자중계
- 로그인, 개인화, 즐겨찾기 팀 저장
- 예측 모델링 / 승부 예측
- 모바일 네이티브 앱
- 상업적 재배포

## 4. 시스템 구성

```
크롤러(src/crawl_*.py) ──> data/raw/*.csv
                              │
가공(src/build_*.py) ─────────┴──> data/processed/*.csv
                                        │
                              update_daily.py --db
                                        │
                                  PostgreSQL (13 테이블)
                                        │
                              FastAPI (kbo-dashboard/backend)
                                        │
                              React SPA (kbo-dashboard/frontend)
```

- 갱신 트리거: cron → `scripts/update_kbo_daily.sh` (flock으로 중복 실행 방지)
- CSV가 1차 진실, DB는 API 서빙용 사본. `--db` 없이 CSV만 갱신하면 API에 반영 안 됨.
- 배포: Docker Compose 5서비스 — `frontend`(React 빌드, `:3000`) / `web`(레거시 정적, `:8000`) /
  `backend`(`:8001`) / `postgres`(`:5433`) / `pgadmin`(`:5050`)

### 데이터 출처와 리스크

| 출처 | 가져오는 것 | 리스크 |
| --- | --- | --- |
| KBO 공식 | 순위, 일정/결과, 타자·투수 기록, 관중, 경기시간, 등록선수 | ASP.NET 폼 기반 → 페이지 구조 변경에 취약 |
| 네이버 스포츠 | 투구 존 좌표, 선수 시즌 기록 | 문서화 안 된 내부 응답 구조 |
| Statiz | 보조 기록 | 구조 변경 시 무단 실패 |

**공개 API가 아니다.** 출처가 바뀌면 파서는 예외 대신 빈 결과를 뱉고 파이프라인이 조용히 성공한다.
이 실패 모드를 막는 게 `src/csv_guard.py` — 0행 저장을 거부하고 기존 CSV를 지킨다.
2026-08-31 기준 CSV를 쓰는 **모든** 크롤러·가공 모듈이 이 가드를 경유하며(`to_csv` 직접 호출 0건),
행 수는 맞는데 값이 깨진 경우도 정합성 규칙 V-01~08로 함께 거부한다(REQUIREMENTS DR-02·DR-07).

- 매일 02:00 KST 자동 갱신이 사람 손 없이 7일 연속 성공한다.
