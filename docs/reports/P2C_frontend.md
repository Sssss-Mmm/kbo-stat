## 2. API 응답 요약

- `seasons`: 시즌마다 `schedule`(첫·마지막 날짜, 마지막 경기일, 종료·무승부·취소·예정 수, 출처·수집 시각) · `standings`(팀 수, 출처) · `box_games`(박스스코어 경기 수: 2025 = 720, 나머지 0) · `postseason: not_collected`. `meta`: `publication: private_pending_rights`, `updates: paused`, `last_collected_at`(2026-10-22 02:00 KST), `collection_policy`.
- `schedule`: 경기마다 `status`·`cancel_reason`·`doubleheader`(1·2, 단일 null)·`has_box`(네이버 원본이 있는 경기만 true). 빈 결과 `reason`: `no_games`(시즌 범위 안 쉬는 날) / `out_of_range`(개막 전·종료 후·포스트시즌) / `season_not_held`. 422: 인자 없음·`date` 와 `season/month` 동시.
- `standings`: 팀마다 계산값(`rank`·`tie`·승패무·`pct`·`games_behind`·`last10`·`streak`·`home`·`away`)과 **원본값을 별도 필드** `source`(+ `games_behind_basis`), `check`(`status` match/mismatch/not_compared, 불일치 `fields`, `rank` match/tie_resolved_by_source/differs). `coverage`: season_final / partial / after_last_played / before_first_game. 날짜 기준(partial)은 원본(시즌 최종)과 비교하지 않는다. 없는 시즌 404.
- `home`: 기준 배너, 계산 순위 + 원본 순위, 마지막 경기일 경기, 시즌 목록.

## 6. 공개 정책 점검

- 새 API 는 인증이 없다 — 비공개는 **네트워크 바인딩**으로만 지켜진다. 점검 중 `kbo_frontend` 가 `3000:80`(모든 인터페이스)으로 열리게 돼 있고 nginx 가 `/api/` 전체를 프록시하는 것을 발견 → `127.0.0.1:3000:80` 으로 고쳤다(백엔드·DB·pgAdmin 은 이미 127.0.0.1). 컨테이너를 다시 만들 때 적용되며, 현재 `kbo_frontend` 는 정지 상태라 지금 열린 포트는 없다.
- CORS 는 localhost:3000 출처만.
- `meta.publication: private_pending_rights` 는 표시용 표지다(강제 수단 아님).
- 새 API 모듈에 외부 요청 코드 없음. KBO·네이버 수집 차단(`fetch_guard`) 그대로, 일일 cron 주석 처리 그대로.

## 7. 배포 준비

- 의존성 고정: `backend/requirements.lock`(전이 포함 39개, 테스트한 이미지의 `pip freeze`) — Dockerfile 은 이 파일만 `--no-deps` 로 설치하고 `pip check`. 베이스 이미지 3개 digest 고정. 프론트는 `package-lock.json` + `npm ci`.
- 재현성: 캐시 빌드와 `--no-cache` 빌드 — 백엔드 패키지 목록 동일(= lock), 프론트 산출물 바이트 단위 동일.
- 최종 후보: `kbo-backend:p2c-final`(d811fc83) · `kbo-frontend:p2c-final`(aa56a790). 롤백 태그 `*:rollback-20260922` 유지. 교체·롤백 절차는 `P2_deploy_readiness.md` 그대로(이미지 이름만 p2c-final).
- DB 백업: P2-C 적재 뒤 `pg_dump` 9.98MB(27개 테이블). 격리 DB 에 복원해 행 수가 운영과 같음을 확인. 이 백업은 소유자(OWNER TO)를 포함해 `kbo_user` 역할이 없는 DB 에는 그대로 복원되지 않는다 — 복원 전에 역할을 만들거나 `--no-owner` 로 뜬다.
- 운영 교체 시 영향: 백엔드·프론트 컨테이너만 재생성(DB 무중단, API 수 초 중단). 프론트를 다시 만들면 3000 포트가 localhost 전용이 된다.

## 8. 남은 위험

- **이용 권한**: 일정·순위 자료는 모두 KBO 사이트 자동 수집분 — 외부 공개는 승인 전 금지(현재 로컬 바인딩만으로 막음).
- **2026-08-04 경기 반영 시점**: 날짜별 공식 스냅샷과 6일 어긋난다. 우리 날짜 기준 순위는 경기를 예정일에 넣는다 — 서스펜디드 경기라면 완료일 기준과 다를 수 있다.
- **원본 순위 해석**: 포스트시즌 반영 최종 순위라는 해석은 방향 일치에 근거한 추정이다(포스트시즌 자료 없음). 화면에도 "보임·확인 불가"로 적었다.
- **홈 AI 이야기**: 실시간 '오늘의 경기' 카드(AI 경기 이야기 포함)를 홈에서 뺐다. `TodayGames.jsx` 는 남아 있으나 쓰이지 않는다(삭제하지 않음).
- **홈 시즌 선택**: 마지막 경기 결과 칸만 시즌이 바뀌고, 아래 v1 카드들은 v1 활성 시즌(2026) 그대로다.
- **팀명**: 과거 시즌 이름(SK·넥센·현대 등)은 그대로 표시, 엠블럼 없음. 팀명 변경 연결 테이블은 만들지 않았다.
- **구조**: `seasons` 가 시즌별 쿼리를 반복(26시즌 40ms) — 시즌이 늘면 묶음 쿼리로 바꾼다. 날짜별 공식 스냅샷과의 대조·시즌 표시 여부 테이블은 만들지 않았다(공개 결정 때 추가).
- **일일 파이프라인(Codex 3차, P2-C 밖)**: KBO 수집이 꺼진 채 새해 첫 실행이면 `update_daily.py` 가 일정 수집은 건너뛰고 `build_team_game_results.build(year)` 에서 그 해 CSV 가 없어 `FileNotFoundError` 로 멈춘다(`--players` 경로도 같음). 데이터 손상 없이 실패로 끝나고 cron 이 중단돼 있어 지금은 영향 없다. cron 재활성화 전에 '입력 CSV 없으면 파생 빌드 건너뛰기 + 회귀 테스트'를 넣어야 한다 — 추가 개발 금지 지시로 이번에는 고치지 않았다.
- **로컬 이미지**: 중간 후보 이미지(`p2a/p2b-candidate`, `p2c-candidate-1·2`)는 지우지 않고 남겨 두었다.
