## 3. 표현 정책 적용

- 출처를 늘 같이 적는다: "네이버 박스스코어 (KBO 공식 기록의 2차 출처)" / "자체 계산 (네이버 문자중계 투구 데이터)". 두 값을 한 칸에 섞지 않는다.
- KBO: `kbo.status` 가 `kbo_verified` 가 아니면 "KBO 직접 검증 전". 네이버 대조 상태 문구에는 KBO 를 쓰지 않는다(테스트).
- 미확정(null) 값은 '미확정'(기울임·점선 밑줄)으로 — 0 으로 바꾸지 않는다(테스트). 계산 이닝 합계가 모르면 확정분 하한을 따로 적는다.
- 이닝: 정수 아웃 → `5 2/3` (테스트). 비율은 분모 0/null 이면 '-'.
- 타자 규정타석 미지원을 화면에 적고 최소 타수(min_ab, 비율 항목 기본 300)를 쓴다.
- as_of / through_date: "기준 시점" 상자에 각각 입력과 설명(데이터 확보 시점 vs 경기 날짜 기준). as_of 조회 때 경기 점수·상태는 서버가 비우고(일정 이력 없음) 화면이 그 이유를 적는다. 그 시점에 확보하지 않은 선수·경기는 404 → "기준 시점에는 아직 확보하지 않았습니다".
- 로딩·오류(한국어, 기존 `apiError`)·빈 데이터 상태를 모든 화면에서 처리.
- 반응형: 카드 3열 → 1열(880px), 표는 자기 칸에서 가로 스크롤. 좁은 화면에서 공용 헤더 네비가 줄어들지 않아 모든 페이지(v1 포함)가 화면보다 넓어지던 기존 문제를 `.nav { min-width: 0 }` 한 줄로 고쳤다.
- 타입: 실제 v2 응답 구조를 `lib/v2.js` JSDoc typedef 로 정의(프로젝트가 JS 라 TS 대신).

## 4. 검증

- 프론트: `npm test` 10개 파일(신규 `v2.test.js`, `navigation.test.js` 보강) · eslint · `vite build` 통과.
- 실제 화면: 후보 API(독립 환경)에 붙인 Vite 개발 서버를 headless Chrome 으로 캡처 — 데스크톱 1280px·모바일 390px(리더보드·선수·박스스코어·데이터 검증·as_of 상태).
- 백엔드: 83개(+ PostgreSQL 통합 7개, 후보 이미지 안에서) · src 99개 통과.
- Codex: 1차 — 새 원본 옆에 옛 원본 대조 상태가 붙는 문제·as_of 응답의 현재 점수 노출 → 수정. 2차 — NULL 을 건너뛴 SUM 이 그럴듯한 합계·ERA 를 냄 → 합계·비율 null, 리더보드 제외·집계. 3차 — 빈 DB 재구축 때 옛 원본 판본의 줄을 적재하지 않음(as_of 조회 깨짐), 과거 as_of 규정이닝 분모에 그 뒤 경기 포함 → 모든 판본 적재·분모를 as_of·through_date 범위로. **3차 수정은 마지막 라운드 뒤라 Codex 재검증을 받지 않았다**(회귀 테스트 추가, 후보 이미지 안 테스트 85개 통과).

## 5. 남은 위험

- 타율 리더보드 기본 최소 타수 300: 공식 규정타석 미달 선수(96경기 출전)가 1위로 보인다 — 공식 타격왕과 다르다. 규정타석은 타석 수가 없어 계산할 수 없다(화면에 명시).
- 박스스코어 원본은 2025 한 시즌. 2026 은 네이버 수집 중단으로 비어 있다.
- 일정·선수 이름(ref)은 이력이 없다 — as_of 조회에서 이름은 현재 값.
- 프론트 컨테이너(`kbo_frontend`, 4주 전 정지)·백엔드 교체는 하지 않았다. 배포하려면 백엔드 컨테이너 교체(후보 이미지)와 프론트 이미지 재빌드가 필요하다(승인 대상).
