# P2-D 보고서 — 팀 상세 · 선수 검색 · 선수 비교

작성: 2026-10-24 · 운영 컨테이너 교체·재시작·cron 재활성화·자동 수집 재개·외부 공개·커밋/푸시 하지 않음.
재발 방지 A·B·C 는 `P2C_guard.md`, 다른 프로젝트 DB 노출은 `external_db_exposure.md`.

## 1. 구현 범위

새 테이블 없음. 기존 자료와 P2-C 순위·일정 서비스를 묶었다. 선수 ID 는 네이버 시즌 기록·KBO 등록선수 명단·v2 `ref.player` 가 같은 KBO 선수 ID 를 쓴다(확인함).

| 기능 | 화면 | API(신규, v2) | 자료·범위 |
| --- | --- | --- | --- |
| 팀 상세 | `/team?team=&season=` | `GET /api/v2/teams/{team}?season=` | 시즌 기록·홈/원정·최근 10경기: P2-C 계산 순위·일정(2001–2026). 주요 타자·투수(WAR 상위 3)·출전 선수: 네이버 시즌 기록(2007–2026, ID 있음). 2001–2006 은 v1 KBO 기록실 규정 이상 선수(이름만, 상세 연결 불가 — 화면에 명시) |
| 선수 검색 | `/search?q=&team=&season=&role=` (메뉴 '선수 찾기') | `GET /api/v2/players/search` | 이름 부분 일치(띄어쓰기 무시)·팀·시즌·역할. 같은 ID 의 시즌 기록을 한 사람으로 묶고, 동명이인은 ID 로 나눠 팀·포지션·생년월일·투타·시즌 범위·'동명이인 N명'을 보인다. 생년월일·투타는 등록선수 명단(2026 일부)에 있는 선수만 — 없으면 비움(추측 안 함) |
| 선수 비교 | `/compare?role=&a=&b=&sa=&sb=&metric=` | (기존 재사용) 프로필 + v1 `/api/player-stats` + v2 선수 시즌 | 타자끼리·투수끼리. 선수마다 시즌 선택(다른 시즌끼리도). 기본·고급 지표(타자 AVG·OBP·SLG·OPS·wOBA·wRC+·ISO·HR·SB·WAR / 투수 ERA·WHIP·K/9·BB/9·K/BB·IP·SO·QS·WAR), 나은 쪽 굵게, **리그 백분위 막대**(그 시즌 규정 충족 선수 기준), **시즌별 추이 선 그래프**. 출처 줄 + 박스스코어가 있는 시즌(2025)은 검증 상태(항목별 일치/불일치/대조 불가, KBO 원본 대조 전) |
| 선수 상세 연결 | 기존 `/player` 에 '시즌별 기록' 추가 | `GET /api/v2/players/{id}/profile` | 네이버 시즌 기록 전 시즌 표(팀 → 팀 상세 링크, 비교 링크). 박스스코어 자료가 없는 시즌(2026 등)도 시즌별 기록을 보이고, 박스스코어 경기 기록은 2025 만 있다고 안내 |

연결: 순위표·홈 응원팀의 팀 이름 → 그 화면이 보여 주는 시즌의 팀 상세. 팀 상세 선수 → 선수 상세. 검색 결과 → 선수 상세·비교. 가을야구(Race)·팀 분석(Teams)은 기존 v1 팀 분석 그대로.

데이터 정책: 없는 값은 `null` → 화면 '미확정'/'자료 없음'(0 아님), 백분위·추이에서 빠짐(추이는 앞뒤 시즌을 직선으로 이음 — 화면에 명시). 모든 화면에 출처·수집 시각. 수집 코드·외부 요청 없음(파일·DB 읽기만).

### 개발 중 발견·수정

- 타격 기록이 잡힌 투수가 검색·명단에 '타자'로도 나옴 → 같은 시즌 투수 기록이 있으면 타자 줄을 뺌(야수 포지션이 명시된 경우만 남김). 2007–2023 은 포지션이 대부분 비어 있어 포지션만으로는 못 가림.
- **2006 KIA·롯데 등 최근 경기 순서 오류**(실데이터 검사에서 발견): 원본이 같은 시각 더블헤더를 2차전부터 적어 둔 경우 → 순위 계산과 같은 순서(날짜·DH 번호·시각)로 정렬. 회귀 테스트 추가(수정 전 코드에서 실패 확인).
- 검색 300–600ms → 시즌 단위 캐시로 8–17ms.
- 비교 화면: 백분위 숫자가 막대 위에서 안 보임 → 막대 밖으로. 추이 설명 문구를 실제 동작(앞뒤 시즌 직선 연결)에 맞춤. 팀 상세 '마지막 경기' → '리그 마지막 경기일'.

## 6. 남은 위험·한계

- **이용 권한**: 네이버 시즌 기록·KBO 일정·등록선수 명단 모두 자동 수집분 — 외부 공개 금지(로컬 바인딩으로만 막음).
- **검증 범위**: 비교 화면의 시즌 값(네이버 시즌 기록)은 어느 출처와도 직접 대조하지 않았다. 2025 검증 표시는 같은 시즌 **박스스코어 경기 기록**의 검증 상태이며 시즌 값 자체의 검증이 아니다(화면에 명시).
- **이적 선수**: 네이버 시즌 기록은 선수당 시즌 한 팀만 — 시즌 중 이적하면 한 팀 명단에만 나온다(화면에 명시).
- **생년월일·투타**: 등록선수 명단(2026-06~10 스냅샷)에 있는 선수만. 은퇴·과거 선수는 비어 있어 동명이인을 팀·포지션·시즌 범위로 가린다. 2007–2023 은 포지션도 대부분 비어 있다.
- **2001–2006**: 선수 ID 자료가 없어 팀 상세의 선수는 규정 이상 이름만, 검색·비교 대상 아님.
- **팀 이름 변경**(SK→SSG, 넥센→키움 등)은 시즌 당시 이름으로만 — 연결 테이블은 만들지 않았다.
- **추이 그래프**: 기존 `TrendLine` 고정 비율이라 모바일에서 글자가 작다.
- 실제 Docker Desktop 재시작으로 A·B·C 를 확인하는 일은 운영 적용 후 첫 재부팅 때.
